# 게시글 댓글 기능 설계

**Date:** 2026-05-28  
**Status:** Draft

## 개요

게시글 상세 화면에 로그인 사용자 전용 1단 댓글 기능을 추가한다. 댓글은 최신순으로 표시하며, 작성자만 본인 댓글을 수정하거나 삭제할 수 있다. 대댓글, 익명 댓글, 신고, 좋아요는 이번 범위에서 제외한다.

## 목표

- 게시글마다 댓글을 남길 수 있게 한다.
- 로그인한 사용자만 댓글을 작성할 수 있게 한다.
- 댓글 작성자는 본인 댓글을 수정하고 삭제할 수 있게 한다.
- 댓글 목록은 최신순으로 보여준다.
- 현재 Auth.js + Prisma 구조에 맞게 구현한다.

## 비목표

- 대댓글/스레드형 댓글
- 익명 댓글
- 댓글 좋아요/싫어요
- 댓글 신고/차단
- 알림, 멘션, 실시간 스트리밍

## 전제

- 댓글은 “게시글”에만 연결한다.
- 현재 레포에는 게시글 모델이 없으므로, 구현 단계에서 최소한의 `Post` 엔티티와 게시글 상세 화면을 함께 추가한다고 가정한다.
- 로그인/세션은 기존 Auth.js 기반 구조를 그대로 사용한다.
- 댓글 작성은 로그인한 사용자만 가능하다.

## 데이터 모델

### `Post`

게시글의 최소 식별자와 본문 정보를 가진다. 댓글 기능과 함께 도입되는 최소 게시글 엔티티이며, 실제 구현에서는 게시글 목록/상세 화면의 구조에 맞춰 필요한 필드만 둔다.

### `Comment`

- `id`
- `postId`
- `userId`
- `content`
- `createdAt`
- `updatedAt`
- `deletedAt`은 이번 범위에서 제외

관계:
- 하나의 `Post`는 여러 `Comment`를 가진다.
- 하나의 `User`는 여러 `Comment`를 작성할 수 있다.

정렬:
- 기본 조회는 `createdAt desc`

수정 정책:
- 수정 시 `updatedAt` 갱신
- 필요하면 UI에 `수정됨` 배지를 표시한다

삭제 정책:
- 하드 삭제로 시작한다.
- 삭제 후에는 목록에서 즉시 사라진다.

## 권한 규칙

- 댓글 작성: 로그인 사용자만 가능
- 댓글 수정: 작성자 본인만 가능
- 댓글 삭제: 작성자 본인만 가능
- 댓글 조회: 게시글 접근 권한이 있다면 누구나 가능

## 사용자 흐름

### 댓글 조회

1. 사용자가 게시글 상세 페이지를 연다.
2. 서버에서 해당 게시글의 댓글을 최신순으로 불러온다.
3. 각 댓글은 작성자, 작성 시각, 본문, 편집/삭제 액션을 보여준다.

### 댓글 작성

1. 로그인 사용자가 댓글 입력창에 내용을 입력한다.
2. 제출 시 서버에서 로그인 상태와 내용 유효성을 검사한다.
3. 저장 성공 시 목록을 최신순으로 갱신한다.
4. 빈 댓글은 저장하지 않는다.

### 댓글 수정

1. 댓글 작성자만 수정 버튼을 볼 수 있다.
2. 수정 화면에서 내용을 변경한다.
3. 서버가 작성자 일치 여부와 내용 유효성을 검사한다.
4. 저장 성공 시 수정된 내용으로 목록을 갱신한다.

### 댓글 삭제

1. 댓글 작성자만 삭제 버튼을 볼 수 있다.
2. 삭제 전 한 번 확인한다.
3. 서버가 작성자 일치 여부를 검사한 뒤 삭제한다.
4. 삭제 성공 시 목록에서 제거한다.

## UI 구성

- 게시글 본문 아래에 댓글 섹션을 둔다.
- 상단에는 댓글 수와 섹션 제목을 둔다.
- 로그인 상태일 때만 댓글 입력 폼을 보여준다.
- 비로그인 상태에서는 로그인 유도 문구와 로그인 버튼을 보여준다.
- 각 댓글 카드는 본문, 작성자, 시간, 수정/삭제 액션을 포함한다.
- 최신순 정렬이므로 새 댓글이 목록 상단에 위치한다.

## 서버 구조

### 읽기

- 게시글 상세 페이지에서 댓글 목록을 함께 가져온다.
- 댓글 조회는 게시글 상세 렌더링과 같은 경로에서 수행한다.

### 쓰기

- 댓글 생성, 수정, 삭제는 서버 액션 또는 route handler로 처리한다.
- 모든 쓰기 작업은 서버에서 세션을 확인한다.
- 작성자 검증은 세션의 `user.id`와 댓글의 `userId`를 비교해 수행한다.

### 에러 처리

- 로그인하지 않은 사용자가 작성/수정/삭제를 시도하면 로그인으로 유도한다.
- 본인 댓글이 아닌 경우 403 수준의 거절 처리를 한다.
- 빈 문자열, 너무 긴 문자열, 공백만 있는 문자열은 거부한다.
- 게시글이 없거나 댓글이 존재하지 않으면 적절한 빈 상태를 보여준다.

## 검증

- 댓글 생성이 로그인 사용자에게만 허용되는지 확인한다.
- 댓글 수정/삭제가 작성자 본인에게만 허용되는지 확인한다.
- 댓글이 최신순으로 표시되는지 확인한다.
- 댓글 생성 후 목록 갱신이 정상 동작하는지 확인한다.
- 댓글 삭제 후 목록에서 즉시 사라지는지 확인한다.

## 테스트 범위

- 권한 테스트
- 유효성 테스트
- 정렬 테스트
- 생성/수정/삭제 성공 경로 테스트
- 비로그인/비작성자 실패 경로 테스트

## 구현 메모

- 현재 레포는 Auth.js와 Prisma를 이미 사용하므로 댓글도 같은 데이터 계층에 얹는 것이 자연스럽다.
- 게시글 모델이 아직 없다면, 댓글 기능과 함께 최소 게시글 엔티티부터 정리하는 것이 좋다.
- 댓글 기능은 우선 단순한 CRUD로 시작하고, 이후 필요할 때만 편집 이력이나 신고 기능을 추가한다.
