# Global Header Design

## Goal

모든 페이지에서 동일한 상단 헤더를 고정으로 보여준다.

헤더에는 다음이 항상 포함된다.

- 사이트 로고/이름
- `Home` 링크
- `Posts` 링크
- 로그인 상태에 따른 `Sign in` 또는 `Sign out`

## Scope

- 적용 범위는 전체 앱의 루트 레이아웃이다.
- 로그인 상태는 서버에서 읽어 렌더링한다.
- 로그인 상태가 있는 경우 `Sign out` 버튼을 표시한다.
- 로그인 상태가 없는 경우 `Sign in` 링크를 표시한다.
- 기존의 페이지별 서브네비는 유지한다.

## Design

### Structure

- 루트 레이아웃에 전역 헤더 컴포넌트를 배치한다.
- 전역 헤더는 모든 경로에서 동일하게 보인다.
- 페이지별 내용은 헤더 아래에서 렌더링한다.

### Behavior

- `Home`은 `/`로 이동한다.
- `Posts`는 `/posts`로 이동한다.
- `Sign in`은 `/login?callbackUrl=<current-path>`로 이동한다.
- `Sign out`은 서버 액션으로 처리하고, 로그아웃 후 `/`로 이동한다.

### Rendering Rules

- 로그인 여부에 따라 헤더 우측 액션만 바뀐다.
- 헤더는 고정 위치를 유지한다.
- 페이지 콘텐츠는 헤더 높이를 고려해 아래에서 시작한다.

## Constraints

- 기존 Apple 스타일의 검은 상단 바 톤을 유지한다.
- `Home`, `Posts`, `Sign out`는 항상 같은 위치에 있어야 한다.
- 페이지 내부의 서브네비는 제거하지 않는다.

## Validation

- 로그인 상태와 비로그인 상태에서 각각 헤더가 올바르게 보이는지 확인한다.
- 홈, 게시글 목록, 게시글 상세, 새 게시글 작성 페이지에서 모두 동일한 헤더가 보이는지 확인한다.
- 로그아웃 후 `/`로 정상 이동하는지 확인한다.
